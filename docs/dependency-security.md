# 依存性セキュリティ監査

`tennis-organizing-app`の監査方式（確認時のmain: `1b17dda5d6538edc0d1f07031ea4cde830b2231f`）を参考に、draw-labの依存構成へ適用する。別プロジェクトの例外やFirebase固有のチェックは引き継がない。

## CIの実行順序と失敗条件

`.github/workflows/ci.yml`はPull Requestと`main`へのpushで、Node.js 24を使用する。

1. `npm ci`でロックファイルに従ってインストール。
2. `npm run test:security`で監査ポリシーと監査コマンドの異常系を検証。
3. `npm run audit:security`で本番依存（`--omit=dev`）と全依存（`--include=dev`）を別々に監査。
4. 型チェック、既存単体テスト、本番ビルド。
5. `if: always()`で監査レポートをアップロード。

本番依存の指摘はすべて失敗とする。全依存の指摘も、後述の限定例外に一致しない限り、info / low / moderate / high / criticalのすべてで失敗とする。通信失敗、コマンド異常終了、不正JSON、エラー応答、件数の不一致や必須項目の欠落も失敗とする。レジストリ応答を取得できない状態を安全な状態として扱わない。

本番監査に失敗しても全依存の監査は実行する。各要求は120秒のタイムアウトを持つ。失敗した監査より後の通常検証ステップは実行されないため、CI失敗時は最初に失敗したステップとレポートを確認する。

`NODE_ENV=production`等の環境でも全依存を監査するため、全体側には明示的に`--include=dev`を指定する。監査結果はnpmレジストリのアドバイザリ情報に依存する。本設定に定期実行やDependabotの自動更新は含まない。

## レポートとローカル実行

```bash
npm ci
npm run test:security
npm run audit:security
```

監査スクリプトは`npm run`経由で起動する。次のファイルへnpmの応答を保存する。

- `.security-audit/production.json`
- `.security-audit/full.json`

応答が不正JSONの場合も元の応答を残す。応答が空の場合は`{}`を残し、標準エラーへ失敗理由を出力する。取得した両ファイルは、成功・失敗にかかわらずGitHub Actionsの`dependency-audit` artifactへ保存する。隠しディレクトリを保存するため`include-hidden-files: true`を指定し、対象は上記JSONだけに限定する。監査前のインストール等で失敗し、ファイルが存在しない場合はアップロードをスキップする。

ローカルのレポートは`.gitignore`対象。指摘を修正したら、ロックファイルを更新し、監査・関連テスト・ビルドを再実行する。

## 一時例外

`security-audit-exception.json`の現在の設定は`advisory: null`、`expires: null`、`packages: {}`で、一時例外はない。

修正版がない開発依存を一時的に許可する場合は、理由・担当を記録し、次のすべてを限定する。

- `advisory`: 許可するアドバイザリのURL1件。
- `expires`: UTCの日時を明示した有効期限。期限と同時、または期限後は許可しない。
- `packages`: 許可するパッケージ名と正確なインストールバージョン。
- 監査対象の全パスが`node_modules/<package>`であり、ロックファイルの同じパスが`dev: true`かつ指定バージョンと一致すること。
- 依存元の指摘を許可する場合、原因のパッケージも同じ条件で再帰的に許可され、最終原因のアドバイザリが指定URLと一致すること。

本番依存の指摘、Critical、別のアドバイザリ、バージョン変更、未指定のネストした依存パス、原因の循環は許可しない。パッケージ名だけの包括的な除外はできない。期限切れでも脆弱性が解消済みなら監査は成功するため、解消後は例外設定を空へ戻す。

## 検証観点と導入時の記録

確認日: 2026-10-06。検証の前提はロックファイル更新後のNode.js 24環境。

| 観点 | 意図・対象 |
|---|---|
| 機能・正常系 | 本番と全体の監査、正確に限定した開発例外、レポート保存 |
| 非機能・異常系 | 通信・終了コード・解析の失敗を成功扱いにせず、後続レポートも収集 |
| データ・境界値 | 全重大度、期限前／同時／後、バージョン・パス・件数・アドバイザリの一致 |
| 状態遷移 | 開発依存から本番依存への変更、新しい指摘、期限切れが例外を無効化 |
| UI・互換性 | React Router更新後のトーナメント・リーグ遷移、再読み込み、履歴移動、ルートガード |
