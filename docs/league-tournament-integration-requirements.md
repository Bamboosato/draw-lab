# リーグ・トーナメント連携機能 要件定義書

- **対象:** `draw-lab` のリーグからトーナメントを作成する機能
- **文書種別:** 連携機能 要件定義書
- **バージョン:** 0.1.0
- **作成日:** 2026-09-01
- **要件の前提:** `docs/requirements.md`、`docs/league-requirements.md`
- **関連設計:** `docs/league-tournament-integration-design.md`

本書は、保存済みのリーグを元に、順位区分を指定したトーナメントを作成する機能の要件を定義する。本機能は既存のリーグ機能とトーナメント機能を1つの主モデルへ統合するものではなく、リーグからトーナメントへ参加者情報と配置に必要な情報をスナップショットとして引き継ぐものである。

---

## 1. 目的

リーグ戦終了後またはリーグ戦の順位確定後に、リーグの参加者名簿を再入力することなく、順位区分別のトーナメント表を作成できるようにする。

本機能で対象とする連携情報は、次のとおりとする。

- 大会の基本情報
- 選択済み参加者の名簿情報
- リーグのグループ情報
- リーグの順位情報
- 引継ぎ元リーグへの参照情報

リーグの試合結果、勝点、星取表、対戦カードをトーナメントへ引き継いだり、トーナメントの試合結果をリーグへ戻したりすることは、本機能の対象外とする。

---

## 2. 基本方針

### 2.1 主モデルを分離する

リーグとトーナメントは、引き続き別の主モデルとして管理する。

| 項目 | リーグ | トーナメント |
|---|---|---|
| 主モデル | `League` | `Tournament` |
| 参加単位 | `LeagueParticipant` | `Entrant` |
| 主な結果 | `LeagueMatch[]`、`LeagueStanding[]` | `GeneratedDraw` |
| 保存領域 | `leagues` | `tournaments` |

### 2.2 一方向のスナップショット連携とする

- 連携方向はリーグからトーナメントへの一方向とする。
- 作成時点のリーグ情報をトーナメントへコピーする。
- 作成後にリーグを変更しても、既存トーナメントを自動更新しない。
- 最新のリーグ情報から作り直す場合は、改めて「リーグから作成」を実行する。
- 作成したトーナメントには、引継ぎ元リーグと順位区分を記録する。

### 2.3 1トーナメントにつき1順位区分とする

1つのトーナメントは、1つの順位区分だけを持つ。

例:

```text
リーグ1-2位 → トーナメントA
リーグ3-4位 → トーナメントB
```

`1-2位` と `3-4位` を作成する場合は、「リーグから作成」を2回実行する。1回の作成操作で複数トーナメントを一括生成する機能は、初期版では設けない。

作成された各トーナメントは、トーナメント一覧に別々の項目として表示し、個別に編集、生成、プレビュー、JSON出力、削除できるものとする。

### 2.4 順位未入力を許容する

引継ぎ元リーグの対戦カードが確定していれば、順位が未入力でもリーグを選択できるものとする。

- 順位未入力を理由に、基本情報画面への遷移を禁止しない。
- 名簿入力画面で、グループ・順位を手動入力できるようにする。
- 順位が未入力のままでは、順位区分に該当する参加者が確定しないため、生成時に警告またはエラーを表示する。
- 順位を自動推定したり、名簿順を順位として使用したりしない。

## 3. 用語定義

| 用語 | 定義 |
|---|---|
| 引継ぎ元リーグ | トーナメント作成の参照元となる保存済みリーグ |
| リーグ由来トーナメント | 引継ぎ元リーグから作成されたトーナメント |
| 順位区分 | トーナメントへ含める順位の範囲。例: `1-2位` |
| グループ順位 | リーグの各グループ内での順位。全グループ横断の総合順位ではない |
| 共通参加者情報 | 表示名、メンバー、所属、地区、備考など、リーグとトーナメントの双方で扱う情報 |
| 配置メタデータ | グループ、順位、引継ぎ元IDなど、トーナメント配置または出典確認に使う情報 |
| 選択済み参加者 | リーグの名簿上で選出状態となっている参加者 |

---

## 4. 対象範囲

### 4.1 対象機能

- トーナメント一覧の追加アクションから「リーグから作成」を開始する
- 対戦カード確定済みリーグを引継ぎ元として選択する
- 基本情報画面で引継ぎ元リーグと1つの順位区分を指定する
- リーグの基本情報と選択済み参加者を初期値として引き継ぐ
- リーグのグループ・順位を初期値として引き継ぐ
- 未入力のグループ・順位をトーナメント名簿入力画面で手動入力する
- 指定順位区分に該当する参加者でトーナメントを生成する
- グループ・順位を利用して初戦の偏りをbest effortで回避する
- 引継ぎ元情報を保存・JSON出力・復元する
- 作成後のトーナメントを通常のトーナメントと同じ一覧・プレビューで扱う

### 4.2 対象外

- リーグとトーナメントを1つの大会エンティティへ統合すること
- リーグとトーナメントの双方向同期
- リーグの試合結果や勝点をトーナメントの試合結果へ変換すること
- トーナメント結果をリーグの順位へ反映すること
- 順位から自動的にシード番号を設定すること
- 複数順位区分の一括作成
- グループごとに別々のトーナメントを自動作成すること
- 同一チーム、同一参加者、同一メンバーの重複検査を新たに追加すること

---

## 5. 利用フロー

```text
トーナメント一覧
  ↓ 「リーグから作成」
リーグ・順位区分指定ダイアログ
  ・引継ぎ元リーグ
  ・順位区分（1つ）
  ↓ 基本情報へ進む
トーナメント基本情報
  ・引継ぎ元リーグの参照・変更
  ・リーグ概要表示
  ・順位区分（1つ）の参照・変更
  ↓ 次へ
トーナメント名簿入力
  ・共通参加者情報を確認・編集
  ・グループ、順位を確認・手動入力
  ↓ 次へ
オプション設定
  ↓ 生成
トーナメント表プレビュー
```

順位区分を変更した別トーナメントを作成する場合は、トーナメント一覧へ戻り、再度「リーグから作成」を実行する。

## 6. 機能要件

### 6.1 作成開始（LT-F-001）

トーナメント一覧の追加アクションメニューに「リーグから作成」を表示する。

- 押下時はリーグ・順位区分指定ダイアログを表示する。
- ダイアログで引継ぎ元リーグと順位区分を指定し、「基本情報へ進む」を押下した時点で新しいトーナメントを作成する。
- キャンセルまたはEscキーで閉じた場合は、トーナメントを作成しない。
- ダイアログのリーグ候補は対戦カード確定済みのリーグに限定する。
- ダイアログでは、選択中リーグの状態、定員、グループ数、選択済み参加者数をコンパクトな概要として表示する。

### 6.2 引継ぎ元リーグ選択（LT-F-002）

基本情報画面で、引継ぎ元リーグを1件選択できる。

- `matchSelectionStatus` が `confirmed` のリーグだけを選択候補にする。
- `status` が `completed` のリーグも、対戦カード確定済みであれば候補に含める。
- 候補にはリーグ名、開催日、種目名、種目区分、更新日時などを表示する。
- 対戦カード未確定のリーグは候補に表示しない。
- 候補が0件の場合は、確定済みリーグがないことを説明する。

リーグ選択後、次の概要情報を表示する。

| 表示項目 | 内容 |
|---|---|
| 状態 | `status` と対戦カード確定状態を日本語で表示 |
| 定員 | `League.capacity` |
| グループ数 | `League.groups.length`。0の場合は「未作成」と表示 |
| 選択済み | `selection.selectedParticipantIds` の人数 |
| 種目区分 | シングルス、ダブルス、チーム |

リーグの定員は登録上の定員として表示し、実際の選択済み人数とは別項目で表示する。

### 6.3 順位区分指定（LT-F-003）

基本情報画面で、1トーナメント分の順位区分を1つ指定できる。

| 項目 | 内容 |
|---|---|
| 下限順位 | 1以上の整数 |
| 上限順位 | 1以上の整数。引継ぎ元リーグの最小グループ人数以下 |
| 表示 | `N-M位` |

バリデーション:

- 下限・上限は整数であること。
- 下限は上限以下であること。
- 順位は1始まりであること。
- 終了順位は、引継ぎ元リーグの各グループ人数の最小値以下であること。
- `1-2位` は1位と2位を含む、両端を含む範囲とする。
- 1つのトーナメントに複数区分を登録しない。

順位は、複数グループの場合も各グループ内順位として解釈する。全グループをまとめた総合順位は本機能では算出しない。

### 6.4 基本情報の引継ぎ（LT-F-004）

引継ぎ元リーグを選択したとき、次の項目を初期値としてコピーする。

| リーグ | トーナメント | 備考 |
|---|---|---|
| `title` | `title` | `リーグ名（N-M位）`を初期値とする |
| `date` | `date` | その後の編集は可能 |
| `venue` | `venue` | その後の編集は可能 |
| `eventName` | `eventName` | その後の編集は可能 |
| `participantType: individual` | `matchType: singles` | 値の表記差をアダプターで吸収 |
| `participantType: doubles` | `matchType: doubles` |  |
| `participantType: team` | `matchType: team` |  |

引継ぎ作成時の種目区分は、リーグの種目区分と一致させる。引継ぎ作成中に別種目へ変更することはできない。通常のトーナメントとして別種目を作成する場合は、新規作成を使用する。

ドローサイズの初期値は、`リーグのグループ数 × 順位区分に含まれる順位数` とする。既存のドローサイズ候補で表現できない算出値は作成できないものとする。シード数と生成オプションは既存トーナメントの基本情報・オプション設定に従う。リーグ順位をシード番号へ自動変換しない。

基本情報画面で順位区分を変更した場合、大会名とドローサイズは、それぞれ直前の順位区分から自動生成された値と一致している場合に限り、新しい順位区分から再計算した値へ更新する。手動編集済みの値は保持する。新しい順位区分から既存のドローサイズ候補を算出できない場合、ドローサイズは現在値を保持する。引継ぎ元リーグを変更した場合は、この判定を行わず、大会名・ドローサイズを含む現在の基本情報を保持する。

### 6.5 参加者情報の引継ぎ（LT-F-005）

リーグの選択済み参加者を、トーナメントの名簿へ初期値としてコピーする。

引き継ぐ共通情報:

- 表示名
- メンバー名
- 所属
- 地区
- 備考

対象参加者は、リーグの選択済み参加者に限定する。補欠・除外参加者は初期コピーしない。

種目区分別の扱い:

- 個人: 選手名をトーナメントの選手名へ引き継ぐ。
- ダブルス: ペア表示名と2名のメンバーを引き継ぐ。
- チーム: チーム名を必須の表示名として引き継ぎ、チームを1ドロー枠として扱う。メンバー単位の試合結果は扱わない。

チーム種目では、チーム名と所属チームを混同しない。チーム名はトーナメント表に表示する名称、所属チームは同じ所属を避けるための情報として扱う。

### 6.6 グループ・順位の引継ぎと手動入力（LT-F-006）

トーナメント名簿入力画面に、リーグ由来トーナメントだけ表示する配置情報列を追加する。

| 項目 | 初期値 | 編集 |
|---|---|---|
| グループ | リーグのグループ名。グループ未作成時は空欄 | 可能 |
| 順位 | リーグの入力済み順位。未入力時は空欄 | 可能 |

- リーグのグループが作成済みの場合、グループ名を初期値としてコピーする。
- リーグのグループが未作成の場合、グループは空欄とする。
- リーグの順位が入力済みの場合、順位を初期値としてコピーする。
- リーグの順位が未入力の場合、順位は空欄とする。
- 名簿入力画面で空欄のグループ・順位を手動入力できる。
- 共通参加者情報を編集しても、引継ぎ元リーグの保存データは変更しない。
- 参加者を削除または追加した場合、配置情報も対象参加者に合わせて更新する。

順位は正の整数として扱う。順位の未入力は編集中は許可するが、生成時に対象者を確定できない場合はエラーとする。

### 6.7 順位区分による対象者抽出（LT-F-007）

トーナメント生成時、名簿の配置情報を参照して順位区分に該当する参加者を抽出する。

- 下限順位以上、上限順位以下の順位を持つ参加者を対象とする。
- 順位未入力者は自動的に順位を補完しない。
- 順位未入力者がいる場合は警告として人数を表示する。
- 指定区分に該当する有効参加者が不足する場合は、トーナメントを生成できない。
- 参加者が指定区分外であることはエラーではない。
- 生成対象となる参加者が0名または1名の場合は、試合を構成できないためエラーとする。

抽出後の参加者数がドローサイズを超える場合は、既存トーナメントのドローサイズエラーと同じ扱いとする。ドローサイズ未満の場合は、既存のBYE補完を利用する。

### 6.8 グループ・順位を利用した配置（LT-F-008）

抽出された参加者のグループ・順位を、初戦の配置に利用する。

#### 複数グループ

対象者に複数のグループが存在する場合、次の順で初戦の対戦を避ける。

1. 同一グループかつ同一順位
2. 同一グループ
3. 同一順位
4. 既存の所属チーム回避
5. 既存の地区回避

完全に回避できない場合は、ペナルティが最小となる配置を採用する。

#### 単一グループ

対象者が単一グループの場合、初戦で順位の近い参加者同士が対戦しないようにする。

- 順位差が小さい組み合わせほど大きなペナルティを付ける。
- 同順位を最も避ける。
- 順位未入力者には順位に関するペナルティを付けない。
- 既存の所属チーム・地区回避は継続する。

いずれの場合も、制約を満たせない場合があることを画面上で説明可能なbest effortとする。同じ入力、同じ乱数シードでは同じ結果になることを維持する。

配置上の「所属チーム」は、既存トーナメントの所属チーム情報を参照する。チーム名表示そのものを所属チーム判定へ使用しない。

### 6.9 保存・一覧・プレビュー（LT-F-009）

作成したリーグ由来トーナメントは、通常のトーナメントと同じ保存・編集・生成・プレビュー機能を利用できる。

- トーナメント一覧では、順位区分ごとに別項目として表示する。
- 初期大会名には順位区分を付加し、区分を識別できるようにする。
- 例: `春季大会（リーグ 1-2位）`
- 作成後の各トーナメントは個別のIDを持つ。
- 各トーナメントは個別の名簿、オプション、乱数シード、生成結果を持つ。
- プレビューは各トーナメントを個別に開いて表示する。
- 引継ぎ元リーグは変更しない。

### 6.10 引継ぎ元の変更（LT-F-010）

基本情報画面で引継ぎ元リーグを変更した場合は、既にコピー済みの名簿と配置情報が置き換わることを確認する。

- キャンセル時は変更しない。
- 確認時は新しいリーグの参加者、グループ、順位、種目区分を置き換える。
- 大会名、開催日、会場、種目名、ドローサイズ、シード数、生成オプションなど、現在のトーナメント基本情報は自動更新しない。手動編集済みかどうかも判定しない。
- 既存の生成済みドローは破棄し、再生成を要求する。
- 元のリーグのデータは変更しない。

## 7. 入力チェックとメッセージ

### 7.1 エラー

| 条件 | メッセージ例 |
|---|---|
| 引継ぎ元が未選択 | 引継ぎ元のリーグを選択してください。 |
| 対戦カード未確定のリーグを指定 | 対戦カードが確定しているリーグを選択してください。 |
| 下限順位が不正 | 下限順位は1以上の整数で入力してください。 |
| 上限順位が不正 | 上限順位は1以上の整数で入力してください。 |
| 下限が上限を超過 | 終了順位は開始順位以上で指定してください。 |
| 終了順位がグループ人数を超過 | 終了順位は最も人数の少ないグループの人数以下にしてください。 |
| 対象者が0名 | 指定した順位区分に該当する参加者がいません。 |
| 対象者が1名 | 指定した順位区分ではトーナメントを作成できる参加者数が不足しています。 |
| ドローサイズ超過 | 指定した順位区分の参加者数がドローサイズを超えています。 |
| 順位が不正 | 順位は1以上の整数で入力してください。 |

### 7.2 警告

| 条件 | メッセージ例 |
|---|---|
| 順位未入力者が存在 | 順位未入力の参加者がX名います。順位区分の対象外として扱われます。 |
| グループ未入力者が存在 | グループ未入力の参加者がいます。グループに関する配置回避の対象外になります。 |
| 順位重複 | 同じグループ内に同じ順位の参加者がいます。配置はbest effortで行います。 |
| 制約を完全に満たせない | すべての偏りを回避できないため、最もペナルティの低い配置を採用しました。 |

警告のみの場合は、既存トーナメントの警告確認方針に従い、ユーザー確認後に生成できるものとする。

---

## 8. 状態遷移

| 状態 | 可能な操作 |
|---|---|
| 基本情報編集中 | リーグ選択、概要確認、順位区分選択、基本情報編集 |
| 名簿編集中 | 共通情報編集、グループ・順位入力、参加者追加・削除 |
| 生成可能 | 順位区分対象者と通常のトーナメント入力が有効 |
| 警告確認待ち | 順位未入力などの警告を確認して生成 |
| 生成済み | 個別プレビュー、通常のトーナメント編集 |
| 引継ぎ元変更確認待ち | 名簿・配置情報の置き換えを確認 |

リーグ由来トーナメントであっても、作成後は通常のトーナメント編集状態として扱う。リーグ側の確定状態を変更したり、リーグへ戻る操作を追加したりしない。

---

## 9. 保存・JSON要件

- `League` と `Tournament` の保存領域は分離したままとする。
- トーナメント側に引継ぎ元リーグID、リーグ更新日時、順位区分を保存する。
- トーナメント参加者と引継ぎ元参加者の対応関係を保存する。
- グループ・順位は作成時点のスナップショットとして保存する。
- リーグを削除しても、コピー済みの参加者情報とトーナメント表は使用できるものとする。
- リーグが存在しない状態でJSONを復元しても、トーナメントの表示・プレビューを妨げない。
- 旧形式のトーナメントJSONは、引継ぎ情報がない通常トーナメントとして従来どおり復元できる。
- 個別トーナメントJSON、全大会バックアップのいずれでも、連携情報を失わない。
- インポートでトーナメントIDや参加者IDが再発行される場合、内部参照は再構成し、出典元IDは履歴情報として保持する。

---

## 10. 非機能要件

### 10.1 再現性

- 同じ名簿、配置情報、順位区分、ドロー設定、乱数シードでは同じドローを生成する。
- 生成結果には使用した乱数シードを保存する。
- best effortの配置でも、入力とシードが同じなら結果を再現できる。

### 10.2 ローカルファースト

- リーグ情報、名簿、順位、生成結果を外部へ送信しない。
- 連携処理はブラウザ内の保存データだけで完結する。
- リーグまたはトーナメントの保存失敗時は、入力中のデータを失わず再試行できる。

### 10.3 操作性

- リーグ選択後に、状態、定員、グループ数、選択済み人数を確認できる。
- 順位区分の対象人数と未入力人数を確認できる。
- リーグ由来トーナメントであることと順位区分を一覧・基本情報・プレビューで確認できる。
- 名簿入力画面で、グループ・順位の入力対象が既存列と区別できる。

### 10.4 互換性

- 通常の新規トーナメント作成フローを変更しない。
- 既存のリーグ保存・復元・複製フローを変更しない。
- 既存のトーナメントJSONを読み込める。

## 11. テスト方針

テストは、次の観点を先に定義してからケースを詳細化する。

### 11.1 テスト観点

| 観点 | 確認内容 |
|---|---|
| 機能 | リーグ選択、順位区分、引継ぎ、抽出、生成、一覧、プレビュー |
| データ | ID参照、選択済み判定、グループ・順位、スナップショット、JSON往復 |
| UI | メニュー、概要表示、入力欄、警告、状態遷移、区分表示 |
| 非機能 | 再現性、保存失敗、リーグ削除後の利用、性能、ローカル完結 |

### 11.2 正常系

- 対戦カード確定済みリーグを選択できる。
- 状態、定員、グループ数、選択済み人数が表示される。
- 入力済みの基本情報、参加者、グループ、順位が引き継がれる。
- 未入力の順位を名簿入力画面で入力できる。
- 1つの順位区分に該当する参加者で生成できる。
- 作成結果がトーナメント一覧に個別表示される。
- 個別にプレビューできる。

### 11.3 異常系

- 対戦カード未確定リーグが候補に表示されない。
- 引継ぎ元未選択、順位区分不正、対象者不足、ドローサイズ超過で生成できない。
- 順位未入力者がいる場合に警告が表示される。
- リーグ変更時の名簿置換をキャンセルできる。
- JSON復元で引継ぎ元リーグが存在しなくてもトーナメントを利用できる。

### 11.4 境界値

- `1-1位`、`1-N位`、下限と上限が同じ区分。
- 0名、1名、2名、ドローサイズちょうど、ドローサイズ超過。
- グループ数0、1、複数。
- 順位がすべて未入力、一部未入力、最大順位付近。
- 既存の4、8、16、32、64、128ドロー。

### 11.5 状態遷移・競合

- 基本情報保存後に再読込しても引継ぎ設定が保持される。
- 名簿入力中に引継ぎ元を変更した場合の確認と置換が正しく動作する。
- リーグ側を更新・削除した後も、作成済みトーナメントのスナップショットが壊れない。
- 保存失敗時に入力中データが失われない。
- 同じ乱数シードで再生成した結果が一致する。

### 11.6 配置ロジック

- 複数グループで同一グループ・同一順位の初戦対戦を優先的に回避する。
- 単一グループで順位差の小さい初戦対戦を優先的に回避する。
- 所属チーム・地区の既存回避条件が維持される。
- 制約が満たせない場合に、生成を不可能とせずbest effort結果と警告を返す。
- 順位・グループが欠落している参加者が、他の参加者の配置を不正に壊さない。

## 12. 完了条件

- トーナメント一覧から「リーグから作成」を開始できる。
- 基本情報画面で対戦カード確定済みリーグを選択できる。
- 選択したリーグの状態、定員、グループ数、選択済み人数を確認できる。
- 1トーナメントにつき1つの順位区分を指定できる。
- 順位未入力の場合、名簿入力画面で手動入力できる。
- リーグの選択済み参加者を再入力せずに引き継げる。
- グループ・順位を利用して対象者を抽出できる。
- グループ・順位を利用した初戦配置がbest effortで行われる。
- 作成されたトーナメントが一覧に個別表示される。
- 各トーナメントを個別にプレビューできる。
- 引継ぎ元リーグを変更してもリーグデータが破壊されない。
- 既存の通常トーナメント作成・リーグ作成・JSON復元が壊れない。
