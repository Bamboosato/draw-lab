# 画面別仕様書

作成日: 2026-07-02  
対象: draw-lab WEB版トーナメント表作成アプリ PoC  
参照: `docs/requirements.md`

---

## 1. 目的

本書は、`draw-lab` のPoC実装に必要な画面構成、画面ごとの入力項目、操作、状態遷移、バリデーション表示を定義する。

要件の正は `docs/requirements.md` とし、本書は開発指示用に画面単位へ分解した補助仕様とする。

---

## 2. 画面一覧

PoCでは以下の画面を実装対象とする。

| 画面ID | 画面名 | 目的 |
|---|---|---|
| SCR-001 | トーナメント一覧画面 | 保存済みトーナメントを確認・作成・編集する |
| SCR-002 | 基本情報入力画面 | 大会情報とドロー設定を入力する |
| SCR-003 | 名簿入力画面 | 参加者・ペア・所属・シードを入力する |
| SCR-004 | 生成オプション画面 | シード位置・BYE位置・選手配置順序を設定する |
| SCR-005 | プレビュー画面 | 生成済みトーナメント表を確認・保存・出力する |
| SCR-006 | JSONインポート画面 | JSONファイルまたはJSONテキストから復元する |

実装上は、SCR-002〜SCR-005を1つの編集画面内のステップとして扱ってもよい。

---

## 3. 推奨ルーティング

初期実装では、以下のURL構成を推奨する。

| パス | 画面 |
|---|---|
| `/` | SCR-001 トーナメント一覧画面 |
| `/tournaments/new` | SCR-002 基本情報入力画面 |
| `/tournaments/:id/edit/basic` | SCR-002 基本情報入力画面 |
| `/tournaments/:id/edit/entrants` | SCR-003 名簿入力画面 |
| `/tournaments/:id/edit/options` | SCR-004 生成オプション画面 |
| `/tournaments/:id/preview` | SCR-005 プレビュー画面 |
| `/import` | SCR-006 JSONインポート画面 |

ルーティングライブラリの導入は任意とする。PoC初期では、単一画面アプリ内の状態遷移で代替してもよい。

---

## 4. 共通UI仕様

## 4.1 共通ヘッダー

表示項目:

- アプリ名: `draw-lab`
- 現在画面名
- トップへ戻る操作

PoCではログイン機能がないため、ユーザー情報表示は不要。

## 4.2 共通操作ボタン

主要な操作は画面下部または右上に配置する。

| 操作 | 表示方針 |
|---|---|
| 保存 | 入力中データをローカル保存する |
| 次へ | 次のステップへ進む |
| 戻る | 前のステップへ戻る |
| 生成 | トーナメント表を生成する |
| PDF出力 | ブラウザ印刷を起動する |
| JSON出力 | JSONファイルをダウンロードする |

## 4.3 エラー・警告表示

バリデーション結果は以下の2種に分ける。

| 種別 | 表示 | 動作 |
|---|---|---|
| エラー | 赤系のメッセージ領域または行内表示 | 解消するまで生成不可 |
| 警告 | 黄系のメッセージ領域または行内表示 | ユーザー確認後に生成可能 |

警告のみの場合は「警告を確認して生成する」操作を許可する。

## 5. SCR-001 トーナメント一覧画面

## 5.1 目的

ローカル保存済みのトーナメントを一覧表示し、新規作成、編集、複製、削除、JSONインポートへ遷移できるようにする。

## 5.2 表示項目

| 項目 | 内容 |
|---|---|
| 大会名 | `Tournament.title`。未設定の場合は「無題のトーナメント」 |
| 種目名 | `Tournament.eventName` |
| 種目区分 | singles / doubles を日本語表示 |
| 開催日 | `Tournament.date` |
| ドローサイズ | `Tournament.drawSize` |
| 最終更新日時 | `Tournament.updatedAt` |
| 生成状態 | 未生成 / 生成済み |

## 5.3 操作

| 操作 | 動作 |
|---|---|
| 新規作成 | SCR-002へ遷移し、新規Tournamentを作成する |
| 編集 | 対象Tournamentを読み込み、SCR-002または前回編集位置へ遷移する |
| プレビュー | 生成済みの場合、SCR-005へ遷移する |
| 複製 | Tournamentをコピーし、新しいIDを採番する |
| 削除 | 確認ダイアログ後にローカル保存から削除する |
| JSONインポート | SCR-006へ遷移する |

## 5.4 空状態

保存済みトーナメントがない場合は、以下を表示する。

```text
保存済みのトーナメントはありません。
新規作成またはJSONインポートから開始してください。
```

## 5.5 受け入れ条件

- 保存済みトーナメントが一覧表示されること
- 新規作成できること
- 既存トーナメントを編集できること
- 生成済みトーナメントをプレビューできること
- 削除前に確認が表示されること

---

## 6. SCR-002 基本情報入力画面

## 6.1 目的

トーナメント表に表示する大会情報と、生成に必要な基本設定を入力する。

## 6.2 入力項目

| 項目 | 型 | 必須 | 初期値 | 備考 |
|---|---|---|---|---|
| 大会名 | text | 任意 | 空 | 表示用 |
| 開催日 | date または text | 任意 | 空 | 厳密な日付処理はPoCでは不要 |
| 会場 | text | 任意 | 空 | 表示用 |
| 種目名 | text | 任意 | 空 | 例: 男子シングルス |
| 種目区分 | select | 必須 | singles | singles / doubles |
| ドローサイズ | select | 必須 | 16 | 4, 8, 16, 32, 64, 128 |
| シード数 | select または number | 任意 | 0 | 0, 2, 4, 8, 16を基本候補 |

## 6.3 操作

| 操作 | 動作 |
|---|---|
| 保存 | 入力値をTournamentへ保存する |
| 次へ | 入力値を保存し、SCR-003へ遷移する |
| 一覧へ戻る | SCR-001へ戻る |

## 6.4 バリデーション

| 条件 | 種別 | メッセージ |
|---|---|---|
| 種目区分が未選択 | エラー | 種目区分を選択してください |
| ドローサイズが未選択 | エラー | ドローサイズを選択してください |
| シード数がドローサイズを超える | エラー | シード数はドローサイズ以下にしてください |
| シード数が負数 | エラー | シード数は0以上にしてください |

## 6.5 受け入れ条件

- 基本情報を入力・保存できること
- ドローサイズを選択できること
- シングルス / ダブルスを切り替えられること
- 入力値が次画面に保持されること

## 7. SCR-003 名簿入力画面

## 7.1 目的

参加者名簿を入力・編集し、シード番号、所属チーム、地区を設定する。

## 7.2 表示切替

`Tournament.matchType` により入力列を切り替える。

### シングルス列

| 列 | 内容 | 編集 |
|---|---|---|
| No | 行番号または表示順 | 任意 |
| シード | シード番号 | 可 |
| 選手名 | 選手名 | 可 |
| 所属チーム | 所属 | 可 |
| 地区 | 地区 | 可 |
| ランキング | 1〜9999の整数 | 可 |
| 操作 | 行削除など | 可 |

### ダブルス列

| 列 | 内容 | 編集 |
|---|---|---|
| No | 行番号または表示順 | 任意 |
| シード | シード番号 | 可 |
| 選手名1 | ペア1人目 | 可 |
| 選手名2 | ペア2人目 | 可 |
| 所属チーム1 | 選手1の所属 | 可 |
| 所属チーム2 | 選手2の所属 | 可 |
| 同チーム扱い | 同一チーム扱いにする短いグループ文字列（1〜5文字） | 可 |
| 地区 | 地区 | 可 |
| ランキング | 1〜9999の整数 | 可 |
| 操作 | 行削除など | 可 |

## 7.3 操作

| 操作 | 動作 |
|---|---|
| 行追加 | 空行を1行追加する |
| 行削除 | 対象行を削除する |
| 空行削除 | 完全空行を削除する |
| 貼り付け | TSV / CSV形式を解析し表へ反映する |
| 入力チェック | バリデーションを実行する |
| 戻る | SCR-002へ戻る |
| 次へ | エラーがなければSCR-004へ遷移する |

完全空行は次へ進む際に自動除外しない。不要な行は、行削除または空行削除で明示的に削除してから次へ進む。

## 7.4 ペースト仕様

Excel / Googleスプレッドシートからのコピーを想定し、タブ区切りTSVを優先して解析する。

CSV貼り付けも受け付ける。

解析時の方針:

- 先頭行がヘッダーらしい場合は、ヘッダーとして扱う
- ヘッダーがない場合は現在の表示列順として扱う
- 空行は無視する
- 余分な列は無視する
- 不足列は空値として扱う

## 7.5 バリデーション

| 条件 | 種別 | メッセージ |
|---|---|---|
| 選手名が未入力 | エラー | 選手名を入力してください |
| ダブルスで選手名が片方のみ入力 | 警告 | ダブルスの選手名が片方のみ入力されています |
| 参加者数がドローサイズを超える | エラー | 参加者数がドローサイズを超えています |
| シード番号が数値でない | エラー | シード番号は数値で入力してください |
| 同一選手名が重複 | 警告 | 同じ選手名が複数行にあります |
| 有効参加者が0件 | エラー | 参加者を1件以上入力してください |

## 7.6 表示補助

- 現在の有効参加者数を表示する
- ドローサイズとの差分からBYE数を表示する
- シード指定人数を表示する
- 警告件数・エラー件数を表示する

例:

```text
参加者数: 13 / ドローサイズ: 16 / BYE: 3 / シード指定: 4
```

## 7.7 受け入れ条件

- シングルス名簿を入力できること
- ダブルス名簿を入力できること
- 表形式で行追加・削除できること
- スプレッドシートから貼り付けできること
- エラーがある場合は次へ進めないこと
- 警告のみの場合は確認後に進めること

## 8. SCR-004 生成オプション画面

## 8.1 目的

トーナメント生成時のシード位置、BYE位置、残り選手の配置順序を設定する。乱数シードは内部的に保持するが、画面上では設定項目として表示しない。

## 8.2 入力項目

| 項目 | 型 | 初期値 | 内容 |
|---|---|---|---|
| 第3・第4シード位置 | radio | テニス方式 | 第3・第4シードの配置方式 |
| シード位置抽選 | radio | JTAルールブック方式 | 抽選しない / JTAルールブック方式 / グランドスラム方式 |
| BYE位置を固定する | checkbox | true | シード位置抽選時もBYE位置を固定する |
| 選手配置順序 | radio | メンバーの多いチームから配置 | メンバーの多いチームから配置 / ランダムに配置 / 名簿記載順に配置 |

## 8.3 操作

| 操作 | 動作 |
|---|---|
| 戻る | SCR-003へ戻る |
| 保存 | オプションを保存する |
| 生成 | バリデーション後にトーナメント表を生成し、SCR-005へ遷移する |

## 8.4 バリデーション

| 条件 | 種別 | メッセージ |
|---|---|---|
| 有効参加者数がドローサイズを超過 | エラー | 参加者数がドローサイズを超えています |

## 8.5 受け入れ条件

- シード位置抽選方式を選択できること
- BYE位置固定を選択できること
- 選手配置順序を選択できること
- 生成ボタンでプレビューへ進めること

---

## 9. SCR-005 プレビュー画面

## 9.1 目的

生成されたトーナメント表を確認し、保存、再生成、JSON出力、PDF出力を行う。

## 9.2 表示項目

| 項目 | 内容 |
|---|---|
| 大会名 | Tournament.title |
| 開催日 | Tournament.date |
| 会場 | Tournament.venue |
| 種目名 | Tournament.eventName |
| ドローサイズ | Tournament.drawSize |
| 生成日時 | GeneratedDraw.generatedAt |
| トーナメント表 | SVG / HTML renderer の出力 |

## 9.3 トーナメント表表示内容

- 選手名
- ダブルスの場合は選手名1・選手名2
- 所属チーム
- 地区
- シード番号
- BYE
- トーナメント線

## 9.4 操作

| 操作 | 動作 |
|---|---|
| 保存 | TournamentとGeneratedDrawをローカル保存する |
| 再生成 | 内部的に新しい乱数シードを生成して再生成する |
| 基本情報へ戻る | SCR-002へ戻る |
| 名簿へ戻る | SCR-003へ戻る |
| オプションへ戻る | SCR-004へ戻る |
| JSON出力 | Tournament一式をJSONとして保存する |
| PDF出力 | `window.print()` を実行する |
| 一覧へ戻る | SCR-001へ戻る |

## 9.5 再生成仕様

再生成では、画面には表示しない内部乱数シードを新規採番する。

## 9.6 PDF印刷仕様

印刷時は以下とする。

- 操作ボタンを非表示にする
- A4横向きを基本とする
- 表が見切れないよう余白を設定する
- 背景装飾は最小限にする
- 64ドロー以上は縮小表示を許容する

## 9.7 受け入れ条件

- 生成済みトーナメント表が表示されること
- 再生成できること
- 生成結果に内部乱数シードが保持されること
- JSON出力できること
- ブラウザ印刷を起動できること
- 保存後、一覧から再表示できること

## 10. SCR-006 JSONインポート画面

## 10.1 目的

JSONファイルまたはJSONテキストからトーナメントデータを復元する。

## 10.2 入力方式

| 方式 | 内容 |
|---|---|
| ファイル選択 | `.json` ファイルを読み込む |
| テキスト貼り付け | JSONテキストを貼り付ける |

## 10.3 操作

| 操作 | 動作 |
|---|---|
| JSON読込 | JSONを解析する |
| 内容確認 | Tournamentとして妥当か確認する |
| インポート | 新しいTournament IDを採番して保存する |
| 一覧へ戻る | SCR-001へ戻る |

## 10.4 バリデーション

| 条件 | 種別 | メッセージ |
|---|---|---|
| JSONとして不正 | エラー | JSONを解析できません |
| 必須フィールド不足 | エラー | トーナメントデータとして必要な項目が不足しています |
| drawSizeが不正 | エラー | ドローサイズが不正です |
| entrantsが配列でない | エラー | 名簿データが不正です |
| generatedDrawが存在するがslots不正 | 警告 | 生成済みドローを復元できない可能性があります |

## 10.5 受け入れ条件

- JSONファイルから復元できること
- JSONテキスト貼り付けから復元できること
- 不正JSONではエラーを表示すること
- インポート後、一覧に表示されること

## 11. 主要状態遷移

```text
SCR-001 一覧
  ├─ 新規作成 → SCR-002 基本情報
  ├─ 編集 → SCR-002 / SCR-003 / SCR-004
  ├─ プレビュー → SCR-005 プレビュー
  └─ JSONインポート → SCR-006 JSONインポート

SCR-002 基本情報
  ├─ 次へ → SCR-003 名簿入力
  └─ 一覧へ戻る → SCR-001 一覧

SCR-003 名簿入力
  ├─ 戻る → SCR-002 基本情報
  └─ 次へ → SCR-004 生成オプション

SCR-004 生成オプション
  ├─ 戻る → SCR-003 名簿入力
  └─ 生成 → SCR-005 プレビュー

SCR-005 プレビュー
  ├─ 基本情報へ戻る → SCR-002 基本情報
  ├─ 名簿へ戻る → SCR-003 名簿入力
  ├─ オプションへ戻る → SCR-004 生成オプション
  └─ 一覧へ戻る → SCR-001 一覧

SCR-006 JSONインポート
  ├─ インポート成功 → SCR-001 一覧
  └─ 一覧へ戻る → SCR-001 一覧
```

---

## 12. 実装メモ

- UIは見栄えよりも入力しやすさと生成結果確認を優先する
- 名簿入力は表形式を基本とする
- 表示テキストは日本語を基本とする
- ドメインロジックはUIコンポーネントに直書きしない
- 画面コンポーネントは、domain層の関数を呼び出すだけに近づける
- 印刷用CSSは初期段階から用意する
