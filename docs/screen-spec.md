# 画面別仕様書

作成日: 2026-07-02  
更新日: 2026-08-21
対象: draw-lab WEB版トーナメント表作成アプリ PoC（正式リリース版 1.0.0）
参照: `docs/requirements.md`

---

## 1. 目的

本書は、`draw-lab` のPoC実装に必要な画面構成、画面ごとの入力項目、操作、状態遷移、バリデーション表示を定義する。

要件の正は `docs/requirements.md` とし、本書は開発指示用に画面単位へ分解した補助仕様とする。

---

## 2. 画面一覧

PoCでは以下の画面を実装対象とする。

| 画面ID | 画面名 | 目的 |
|---|---|---|
| SCR-001 | トーナメント一覧画面 | 保存済みトーナメントを確認・作成・編集する |
| SCR-002 | 基本情報入力画面 | 大会情報とドロー設定を入力する |
| SCR-003 | 名簿入力画面 | 参加者・ペア・所属・シードを入力する |
| SCR-004 | オプション設定画面 | シード位置・BYE位置・選手配置順序を設定する |
| SCR-005 | プレビュー画面 | 生成済みトーナメント表を確認・保存・出力する |
| SCR-006 | 大会情報の復元画面 | 個別大会データの追加または全大会バックアップの全置換復元を行う |

実装上は、SCR-002〜SCR-005を1つの編集画面内のステップとして扱ってもよい。

---

## 3. 推奨ルーティング

初期実装では、以下のURL構成を推奨する。

| パス | 画面 |
|---|---|
| `/` | SCR-001 トーナメント一覧画面 |
| `/tournaments/new` | SCR-002 基本情報入力画面 |
| `/tournaments/:id/edit/basic` | SCR-002 基本情報入力画面 |
| `/tournaments/:id/edit/entrants` | SCR-003 名簿入力画面 |
| `/tournaments/:id/edit/options` | SCR-004 オプション設定画面 |
| `/tournaments/:id/preview` | SCR-005 プレビュー画面 |
| `/import` | SCR-006 大会情報の復元画面 |

ルーティングライブラリの導入は任意とする。PoC初期では、単一画面アプリ内の状態遷移で代替してもよい。

画面内のリンク、ボタン、メニューおよび入力状態に応じた自動リダイレクトによる画面遷移には View Transitions API を使用する。サイドバーなどの共通領域は固定し、本文領域だけを短時間のフェードで切り替える。

View Transitions API に未対応の場合は通常遷移へフォールバックし、画面操作を妨げない。`prefers-reduced-motion: reduce` の場合はView Transitionを開始せず、アニメーションなしで遷移する。ブラウザ標準の戻る・進む操作は通常遷移として扱う。

## 4. 共通UI仕様

## 4.1 共通ヘッダー

表示項目:

- アプリ名: `draw-lab`
- 現在画面名
- トップへ戻る操作

PoCではログイン機能がないため、ユーザー情報表示は不要。

## 4.2 編集フロー表示

SCR-002〜SCR-005では、画面上部に「基本情報 → 名簿入力 → オプション設定 → 生成・プレビュー」の進捗ステッパーを表示する。現在のステップは青い番号円と下線で表示し、現在より前のステップはチェックマークと青い接続線で完了状態を示す。現在より後のステップは薄いグレーで表示し、角丸ボタンの集合に見えないコンパクトな進捗表示とする。ステッパーは本文領域を基準に中央配置し、番号円の間隔を抑えた横幅で表示する。狭い画面では横スクロール可能な一列表示とする。

各画面の本文先頭の縦方向の余白は、トーナメント一覧画面を基準に統一する。デスクトップ表示ではコンテンツ上端から本文ブロックを8px上げ、狭い画面では通常のコンテンツ余白に戻す。

## 4.3 共通操作ボタン

主要な操作は画面下部または右上に配置する。

通常の操作ボタンは高さ36px、フォントサイズ14pxを基本とする。アイコン専用ボタン、テーブルのソート操作など、用途上の専用サイズがあるコントロールは個別仕様を優先する。

| 操作 | 表示方針 |
|---|---|
| 保存 | 入力中データをIndexedDBへ保存する |
| 次へ | 次のステップへ進む |
| 戻る | 前のステップへ戻る |
| 生成 | トーナメント表を生成する |
| PDF出力 | ブラウザ印刷を起動する |
| 個別JSON出力 | 選択中の1大会をJSONファイルとしてダウンロードする |
| 全大会バックアップ | IndexedDB内の全大会を1つのJSONファイルとしてダウンロードする |

## 4.4 エラー・警告表示

バリデーション結果は以下の2種に分ける。

| 種別 | 表示 | 動作 |
|---|---|---|
| エラー | 赤系のメッセージ領域または行内表示 | 解消するまで生成不可 |
| 警告 | 黄系のメッセージ領域または行内表示 | ユーザー確認後に生成可能 |

警告のみの場合は「警告を確認して生成する」操作を許可する。

## 4.5 PWA状態表示

PWAの状態は、ユーザーの判断や操作が必要な場合に限って表示する。Service Worker登録済みでオンラインの通常状態を「PWA準備完了」などの中立メッセージとして常時表示しない。

| 状態 | 表示 | 操作 |
|---|---|---|
| 初回読み込み中 | 既存のアプリ読み込み表示を使用 | 操作不可 |
| オフライン | 画面上部に「オフラインで利用中」と表示 | キャッシュ済み機能と保存状態を確認できる |
| 更新あり | `role="status"` の通知領域に「新しいバージョンがあります」と表示 | 「更新」「後で」を選択できる |
| 更新適用中 | 「更新しています」と表示 | 二重実行不可 |
| 更新失敗 | 「更新できませんでした。再試行してください」と表示 | 再試行できる |
| 初回オフラインでアプリシェル未取得 | 起動不能の理由をエラー表示 | オンライン復帰後の再読み込みを案内する |
| Service Worker非対応 | PWA状態を表示しない | 通常のWebアプリとして利用できる |

更新操作は `IndexedDB` の保存状態が `saving` の間は開始しない。未保存の入力を破棄する可能性がある強制再読み込みや自動 `skipWaiting` は行わない。PWAインストール操作は初期実装ではブラウザ標準UIに任せ、アプリ内インストールボタンを必須としない。

## 5. SCR-001 トーナメント一覧画面

## 5.1 目的

IndexedDBに保存済みのトーナメントを一覧表示し、新規作成、編集、複製、削除、JSONインポート / 復元、全大会バックアップを実行できるようにする。

## 5.2 表示項目

| 項目 | 内容 |
|---|---|
| 大会名 | `Tournament.title`。未設定の場合は「無題のトーナメント」 |
| 種目名 | `Tournament.eventName` |
| 種目区分 | singles / doubles を日本語表示 |
| 開催日 | `Tournament.date` |
| ドローサイズ | `Tournament.drawSize` |
| 最終更新日時 | `Tournament.updatedAt` |
| 生成状態 | 未生成 / 生成済み |

一覧表の上部には、全トーナメント数、生成済み数、編集中数を1つのコンパクトなサマリー帯として表示する。生成済みドローが有効な大会を生成済み数へ含め、未生成は編集中数へ含める。サマリー帯は一覧表と同じ横幅を維持し、3つの件数セルを左側へ詰めて表示する。保存方式などの内部実装情報は通常の概要帯へ表示しない。

一覧画面では、表示領域に収まるデスクトップ幅で不要なページ全体の上下・左右スクロールを表示しない。画面幅が不足する場合に限り、一覧表の枠内で横スクロールを使用する。編集画面の固定フッター用に確保する下部余白は一覧画面には適用しない。

## 5.3 操作

| 操作 | 動作 |
|---|---|
| 新規作成 | SCR-002へ遷移し、新規Tournamentを作成する |
| 編集 | 未生成の場合はSCR-002へ直接遷移する。生成済みの場合はプルダウンを表示し、SCR-002基本情報、SCR-003名簿入力、SCR-004オプション設定から遷移先を選択する |
| プレビュー | 生成済みの場合だけSCR-005へ遷移する |
| 複製 | Tournamentをコピーし、新しいIDを採番する |
| 削除 | 確認ダイアログ後にIndexedDBから削除する |
| 個別JSON出力 | 対象Tournament一式をJSONとしてダウンロードする |
| 全大会バックアップ | 保存済みの全Tournamentを1つのバックアップJSONとしてダウンロードする |
| JSONインポート / 復元 | SCR-006へ遷移する |
| 開催日で並び替え | `開催日` 見出しをクリックするたび、近い順（昇順）と遠い順（降順）を切り替える |
| 最終更新で並び替え | `最終更新` 見出しをクリックするたび、新しい順（降順）と古い順（昇順）を切り替える |

未生成の大会ではプレビューボタンを無効化し、背景色、文字色、枠線、カーソルを有効状態と区別できる表示にする。ツールチップには、トーナメント表が未生成のためプレビューできないことを表示する。

一覧右上は `新規作成` ボタン、その右に横3点の追加アクションボタンを配置する。デスクトップ表示では一覧上部の余白を調整し、`新規作成` ボタンの上端をサイドバーの `トーナメント` 項目の上端に合わせる。サイドバーの `リーグ表` 項目は、上端を一覧の概要帯に合わせる。全大会バックアップと復元は、右上へ個別ボタンとして並べず追加アクションメニュー内へ配置する。

一覧の初期表示順は最終更新が新しい順（降順）とする。`開催日` と `最終更新` の見出し右側には、未選択時は `⇅`、選択中は昇順 `▲` または降順 `▼` を表示する。別の列へ切り替えた場合、開催日は昇順、最終更新は降順から開始する。日付が未設定または不正な大会は並び方向にかかわらず末尾に表示し、同値の場合は切り替え前の相対順を維持する。

| メニュー | グループ | 表示名 | ツールチップ |
|---|---|---|---|
| 一覧右上の追加アクション | バックアップ | アイコン + `全大会バックアップ` | `全大会をファイルへバックアップ` |
| 一覧右上の追加アクション | 復元 | アイコン + `大会情報の復元` | `大会情報をファイルから復元` |
| 各大会行の追加アクション | 大会情報 | アイコン + `複製` | `大会情報(個別)を複製` |
| 各大会行の追加アクション | 大会情報 | アイコン + `出力` | `大会情報(個別)をファイルへ出力` |
| 各大会行の追加アクション | 大会情報 | アイコン + `削除` | `大会情報(個別)を削除` |

各大会行の `削除` は、`複製`、`出力` と区切り線で分け、危険操作の色で表示する。

## 5.4 保存状態

| 状態 | 表示・操作 |
|---|---|
| 読込中 | 読込中表示を行い、空状態を表示しない |
| 保存可能 | 一覧と操作を表示する |
| 保存中 | 編集内容を画面へ反映しつつ、保存中であることを表示する |
| 保存エラー | 未保存または読込失敗であることを表示し、空一覧と区別する |
| localStorage移行エラー | 元データを保持していることを表示し、再試行可能とする |

## 5.5 空状態

保存済みトーナメントがない場合は、以下を表示する。

```text
保存済みのトーナメントはありません。
新規作成または大会情報の復元から開始してください。
```

## 5.6 受け入れ条件

- 保存済みトーナメントが一覧表示されること
- 新規作成できること
- 既存トーナメントを編集できること
- 生成済みトーナメントをプレビューできること
- 初回生成後に生成対象の入力を有効な内容へ変更すると自動再生成され、生成済みとプレビュー可能な状態を維持すること
- 名簿入力にエラーがある場合は未生成となり、プレビュー操作が無効になること
- 削除前に確認が表示されること
- 読込中・空状態・保存エラーを区別できること
- 全大会バックアップJSONをダウンロードできること
- 初期表示が最終更新の新しい順であること
- 開催日と最終更新の列見出しから昇順・降順を切り替えられること
- 選択中の並び順をアイコンとアクセシビリティ属性で確認できること

## 6. SCR-002 基本情報入力画面

## 6.1 目的

トーナメント表に表示する大会情報と、生成に必要な基本設定を入力する。

## 6.2 入力項目

| 項目 | 型 | 必須 | 初期値 | 備考 |
|---|---|---|---|---|
| 大会名 | text | 任意 | 空 | 表示用 |
| 開催日 | date または text | 任意 | 空 | 厳密な日付処理はPoCでは不要 |
| 会場 | text | 任意 | 空 | 表示用 |
| 種目名 | text | 任意 | 空 | 例: 男子シングルス |
| 種目区分 | select | 必須 | singles | singles / doubles |
| ドローサイズ | select | 必須 | 16 | 4, 8, 16, 32, 64, 128 |
| シード数 | select または number | 必須 | 0 | 0（シードなし）, 2, 4, 8, 16を基本候補 |

必須項目のラベルには、名簿入力画面と同じ赤い `*` を表示する。

## 6.3 操作

| 操作 | 動作 |
|---|---|
| 保存 | 入力値をTournamentへ保存する |
| 次へ | 入力値を保存し、SCR-003へ遷移する |
| 一覧 | SCR-001へ戻る |

生成済みの大会で種目区分、ドローサイズ、シード数を有効な内容へ変更した場合は、直前の乱数シードで自動再生成して生成済み状態を維持する。大会名、開催日、会場、種目名などの表示情報だけを変更した場合は再生成せず生成済み状態を維持する。変更によって名簿入力がエラーになった場合は未生成へ戻す。

## 6.4 バリデーション

| 条件 | 種別 | メッセージ |
|---|---|---|
| 種目区分が未選択 | エラー | 種目区分を選択してください |
| ドローサイズが未選択 | エラー | ドローサイズを選択してください |
| シード数がドローサイズを超える | エラー | シード数はドローサイズ以下にしてください |
| シード数が負数 | エラー | シード数は0以上にしてください |

## 6.5 受け入れ条件

- 基本情報を入力・保存できること
- ドローサイズを選択できること
- シングルス / ダブルスを切り替えられること
- 入力値が次画面に保持されること
- 初回生成後に生成に必要な基本設定を有効な内容へ変更すると自動再生成されること
- 表示情報だけを変更しても生成済み状態を維持すること

## 7. SCR-003 名簿入力画面

## 7.1 目的

参加者名簿を入力・編集し、シード番号、所属チーム、地区を設定する。

## 7.2 表示切替

`Tournament.matchType` により入力列を切り替える。

名簿表は、入力頻度の低い詳細列を初期状態では閉じて表示する。ダブルスは所属チーム1・所属チーム2まで、シングルスは所属チームまでを常時表示し、その右上に開閉記号を置く。閉じている時は `所属チーム1 所属チーム2 ⊕ 操作`、または `所属チーム ⊕ 操作` の並びとし、`⊕` を押すと詳細列を開く。開いている時は `所属チーム1 所属チーム2 ⊖ 同チーム扱い … 操作`、または `所属チーム ⊖ 地区 … 操作` の並びとし、`⊖` を押すと詳細列を閉じる。開閉記号は常時表示する最後の所属チーム列の入力欄右端上部に寄せ、操作列も常時表示する。

詳細列を閉じても入力値や保存データは削除しない。再度開いた時に入力値をそのまま表示し、詳細列の入力・バリデーションを継続する。

### シングルス列

| 列 | 内容 | 編集 |
|---|---|---|
| No | 行番号または表示順 | 任意 |
| シード | シード番号 | 可 |
| 選手名 | 選手名 | 可 |
| 所属チーム | 所属 | 可 |
| 地区 | 地区 | 可 |
| ランキング | 1〜9999の整数 | 可 |
| 操作 | 行削除など | 可 |

### ダブルス列

| 列 | 内容 | 編集 |
|---|---|---|
| No | 行番号または表示順 | 任意 |
| シード | シード番号 | 可 |
| 選手名1 | ペア1人目 | 可 |
| 選手名2 | ペア2人目 | 可 |
| 所属チーム1 | 選手1の所属 | 可 |
| 所属チーム2 | 選手2の所属 | 可 |
| 同チーム扱い | 同一チーム扱いにする短いグループ文字列（1〜5文字） | 可 |
| 地区 | 地区 | 可 |
| ランキング | 1〜9999の整数 | 可 |
| 操作 | 行削除など | 可 |

## 7.3 操作

| 操作 | 動作 |
|---|---|
| 詳細列開閉 | 常時表示する最後の所属チーム列（ダブルスは所属チーム2、シングルスは所属チーム）の右上にある `⊕` / `⊖` を押し、同チーム扱いから右側の詳細列を表示・非表示にする。操作列は常時表示する |
| 行追加 | 非表示の保存済み空行がある場合は次の1行を表示し、ない場合は空行を1行追加する |
| 行削除 | 対象行を削除する |
| 空行削除 | 完全空行を削除する |
| 貼り付け | TSV / CSV形式を解析し表へ反映する |
| 入力チェック | バリデーションを実行する |
| 一覧 | SCR-001へ戻る |
| 戻る | SCR-002へ戻る |
| 次へ | エラーがなければSCR-004へ遷移する |

完全空行は画面および保存データに残したまま次へ進める。検証・生成時だけ対象から除外し、有効参加者数およびBYE数の計算には含めない。「空行削除」を実行した場合に限り、完全空行を保存データから削除する。完全空行はBYEの明示指定として扱わない。

初期表示行数は、ドローサイズと、入力が存在する最後の行番号の大きい方とする。ドローサイズを超える末尾の完全空行は保存データに保持したまま非表示とし、不完全行を含む入力済み行はドローサイズ外でも隠さない。

有効参加者数がドローサイズを超える場合は、名簿入力概要の「有効参加者数」を赤色の背景で表示し、概要帯の右端に「有効参加者数がドローサイズを超過しています。」を赤文字で表示する。複数のエラーがある場合は、先頭のメッセージの末尾に「他」を付けて表示する。ツールチップでもドローサイズ超過を案内する。BYE数は「—」と表示し、「不正」の文言は使用しない。有効参加者数がドローサイズ以下へ戻ると通常表示へ戻す。

基本情報のシード数と名簿のシード指定人数が一致しない場合は、「シード指定」を赤色の背景で表示し、概要帯の右端に「シード指定数が不足しています。」または「シード指定数が超過しています。」を赤文字で表示する。複数のエラーがある場合は、先頭のメッセージの末尾に「他」を付けて表示する。値には括弧書きの状態表示を付けない。ツールチップで基本情報のシード数との不一致を案内し、指定人数が一致すると通常表示へ戻す。

生成済みの大会で名簿を有効な内容へ変更した場合は、保存した乱数シードで自動再生成して生成済み状態を維持する。不完全行、参加者数超過、有効参加者0件などのエラーがある間は生成済みドローを破棄して未生成とするが、乱数シードは保持する。エラー修正後は自動再生成して生成済みへ戻す。参加者行をすべて削除した後に有効な参加者を再入力した場合も同様とし、初回生成後にユーザーによる明示的な再生成を必須としない。完全空行の追加・削除だけでは再生成せず、生成済み状態を維持する。

## 7.4 ペースト仕様

Excel / Googleスプレッドシートからのコピーを想定し、タブ区切りTSVを優先して解析する。

CSV貼り付けも受け付ける。

解析時の方針:

- 先頭行がヘッダーらしい場合は、ヘッダーとして扱う
- ヘッダーがない場合は現在の表示列順として扱う
- 空行は無視する
- 余分な列は無視する
- 不足列は空値として扱う
- 取り込んだ参加者は既存の完全空行を先頭から埋め、空行数を超えた分だけ末尾へ追加する。未使用の完全空行は保持する

## 7.5 バリデーション

| 条件 | 種別 | メッセージ |
|---|---|---|
| 完全空行ではない行で選手名が未入力 | エラー | 選手名を入力してください |
| 完全空行ではないダブルス行で選手名が不足 | エラー | ダブルスの選手名1・選手名2を入力してください |
| 参加者数がドローサイズを超える | エラー | 参加者数がドローサイズを超えています |
| シード番号が数値でない | エラー | シード番号は数値で入力してください |
| 同一選手名が重複 | 警告 | 同じ選手名が複数行にあります |
| 有効参加者が0件 | エラー | 参加者を1件以上入力してください |

## 7.6 表示補助

- 現在の有効参加者数を表示する
- シード指定人数を表示する
- ドローサイズとの差分からBYE数を表示する
- 警告件数・エラー件数を表示する
- 有効参加者数、ドローサイズ、シード指定、BYE数は、名簿表と同じ横幅のコンパクトなサマリー帯として表示する。4つの件数セルは同じ幅で左側へ詰め、右端の状態メッセージ領域にエラー内容を赤文字で表示する。保存方式などの内部実装情報は表示しない

例:

```text
参加者数: 13 / ドローサイズ: 16 / シード指定: 4 / BYE: 3
```

## 7.7 受け入れ条件

- シングルス名簿を入力できること
- ダブルス名簿を入力できること
- 表形式で行追加・削除できること
- 初期状態では同チーム扱いから右側の詳細列が閉じ、常時表示する最後の所属チーム列の右上にある `⊕` で開けること
- 詳細列を開いた状態では同じ位置の `⊖` で閉じられ、操作列は開閉状態にかかわらず表示されること
- 詳細列を閉じても同チーム扱い、地区、ランキングの入力値が保持され、再表示後も編集できること
- スプレッドシートから貼り付けできること
- エラーがある場合は次へ進めないこと
- 警告のみの場合は確認後に進めること
- 完全空行を保持したまま次へ進み、生成後も保存データに空行が残ること
- 所属チームなど一部だけ入力された不完全行はエラーになること

## 10. SCR-006 大会情報の復元画面

## 10.1 目的

DrawLabから出力した大会情報ファイルを読み込み、個別大会データは新しい大会として追加し、全大会バックアップは確認後にIndexedDB内の全大会を置き換えて復元する。一般ユーザーへJSON本文は表示しない。

## 10.2 入力方式

| 方式 | 内容 |
|---|---|
| ファイル選択 | DrawLabから出力した `.json` ファイルをクリック、タップ、ドラッグ＆ドロップで選択する |
| サンプルデータを使用 | ファイル選択より控えめな補助操作として配置し、画面内でサンプル大会を内部読込する。JSON本文は表示しない |

JSONテキストを直接入力するテキストエリアは設けない。ファイル選択後は追加の読込・実行ボタンを介さず自動的に解析し、未選択時はエラーを表示しない。サンプルデータを選択した場合も同様に自動解析する。

デスクトップ表示では、画面本文先頭の案内文とサイドバーの `トーナメント` 項目を垂直方向の中央位置で合わせる。モバイル表示では通常のコンテンツ余白を使用する。

ファイル選択パネルの `大会情報ファイル` と読込結果パネルの `読込結果` は、同じ文字サイズ・太さを使用し、垂直方向の中央位置を合わせる。

ファイル選択UIは、ブラウザ標準のファイル入力を視覚的に隠し、以下を備えた選択エリアとして表示する。ネイティブの `input[type="file"]` はDOMに保持し、選択エリアおよびラベル操作から起動できるようにする。

- ファイル選択を示すアイコン
- `ファイルをドラッグ＆ドロップ`
- `または`
- `ファイルを選択`
- 対応形式の補足
- `ファイルを選択すると、自動的に処理を開始します。` の説明

選択エリア全体をクリックまたはタップでき、キーボードのEnter / Spaceでもファイル選択ダイアログを開けるようにする。ドラッグ中は背景色または境界色を変更し、受付状態を示す。ファイル入力の値は選択後にリセットし、同一ファイルの再選択を可能にする。

## 10.3 解析結果表示

ファイル読込後、保存処理を行う前に以下の要約を表示する。JSON本文は表示しない。

| 項目 | 内容 |
|---|---|
| データ種別 | 個別大会 / 全大会バックアップ |
| schemaVersion | 検出したバージョン。個別大会の既存形式では「未設定」と表示可 |
| 復元対象数 | 個別大会は1件、全大会バックアップは `tournaments.length` |
| 現在の大会数 | IndexedDBに保存されている大会数 |
| 実行結果 | 追加 / 全置換 |
| 警告 | 個人情報を含むこと、全置換では現在の全大会が削除されること |

全大会バックアップでは大会名、開催日、参加者数、生成状態を一覧で確認できるようにする。大量大会の場合は全件を描画せず、件数と先頭の一部を表示してもよい。

## 10.4 操作

| 操作 | 動作 |
|---|---|
| ファイル読込 | ファイルを解析し、種別判定と全データ検証を行う。IndexedDBは変更しない |
| サンプルデータを使用 | サンプルの個別大会を内部読込し、要約と検証結果を表示する |
| 個別大会を追加 | 新しいIDを採番し、関連IDを更新してIndexedDBへ1大会を追加する |
| 全大会を復元 | 全置換確認ダイアログを表示する |
| 別のファイルを選択 | ファイル選択ダイアログを再度開く。新しいファイルの選択後に解析結果と確認状態を更新する |
| 一覧へ戻る | IndexedDBを変更せずSCR-001へ戻る |

データ種別に応じて「個別大会を追加」または「全大会を復元」の一方だけを表示する。

## 10.5 全置換確認ダイアログ

全大会バックアップを復元する前に、以下を表示する。

```text
現在保存されている{currentCount}件の大会を削除し、
バックアップ内の{backupCount}件へ置き換えます。
この操作は取り消せません。
```

操作は以下とする。

| 操作 | 動作 |
|---|---|
| キャンセル | ダイアログを閉じ、IndexedDBを変更しない |
| 全大会を置き換えて復元 | 1トランザクションで全置換を開始する |

`backupCount` が0件の場合も「0件へ置き換える」ことを明示し、確認を省略しない。

## 10.6 処理状態

| 状態 | 表示・操作 |
|---|---|
| 未選択 | 選択エリアとサンプル操作を表示し、エラーは表示しない |
| 読み込み中 | ファイル名、`読み込み中`、スピナーを表示し、再選択、ドロップ、サンプル操作を無効化する |
| 処理中 | ファイル名、`処理中`、スピナーを表示し、再選択、ドロップ、サンプル操作を無効化する |
| 完了 | ファイル名と`完了`を表示し、別のファイルを選択できるようにする |
| エラー | ファイル名、`エラー`、エラーメッセージを表示し、別のファイルを選択できるようにする |
| 確認可能 | 解析結果、警告、実行ボタンを表示する |
| 復元中 | 二重実行を防止し、一覧遷移を無効化する |
| 成功 | 復元件数を表示し、SCR-001へ遷移する |
| 失敗 | 復元前データが保持されていることと、失敗理由を表示する |

## 10.7 バリデーション

| 条件 | 種別 | メッセージ |
|---|---|---|
| ファイル形式が不正 | エラー | 大会情報ファイルを読み込めません |
| 個別大会・全大会バックアップのどちらでもない | エラー | 対応していない大会情報ファイルです |
| 必須フィールド不足 | エラー | トーナメントデータとして必要な項目が不足しています |
| drawSizeが不正 | エラー | ドローサイズが不正です |
| entrantsが配列でない | エラー | 名簿データが不正です |
| 個別大会のgeneratedDrawが存在するがslots不正 | 警告 | 生成済みドローを復元できない可能性があります |
| 全大会バックアップのschemaVersionが未対応 | エラー | このバックアップ形式には対応していません |
| 全大会バックアップ内でID重複 | エラー | バックアップ内のIDが重複しています |
| 全大会バックアップ内の参照先が不正 | エラー | バックアップ内の参照関係が不正です |
| IndexedDBの全置換失敗 | エラー | バックアップを復元できませんでした。元のデータは保持されています |

## 10.8 受け入れ条件

- 選択エリアのクリック、タップ、ドラッグ＆ドロップから大会情報ファイルを選択できること
- ネイティブのファイル入力がDOMに保持され、キーボードのEnter / Spaceから選択ダイアログを開けること
- ファイル選択直後に既存処理が1回だけ自動開始され、JSONテキストの直接入力欄や追加の読込・実行ボタンが表示されないこと
- ファイル名と読み込み中・処理中・完了・エラーの状態を文字で確認でき、状態変化が支援技術へ通知されること
- 処理中は再選択、ドラッグ＆ドロップ、サンプル操作による二重実行が防止されること
- 処理完了後に別のファイルおよび同一ファイルを再選択できること
- JSON本文を表示せず、復元判断に必要な要約だけを確認できること
- サンプルデータをJSON本文を表示せずに利用でき、1回だけ自動処理されること
- PCとスマートフォンの双方で選択エリア、状態表示、操作ボタンが横幅に収まること
- 個別大会データを新しい大会として追加できること
- 全大会バックアップの種別と大会数を実行前に確認できること
- 全置換前に現在件数、復元件数、削除警告が表示されること
- 明示的な確認後に全大会を全置換できること

- 復元失敗時に復元前の全大会が保持されること
- 復元成功後、SCR-001に全大会が表示されること

  ├─ 基本情報へ戻る → SCR-002 基本情報
  ├─ 名簿へ戻る → SCR-003 名簿入力
  ├─ オプションへ戻る → SCR-004 オプション設定

SCR-006 JSONインポート / 復元

  ├─ 全大会バックアップを解析 → 全置換確認
  ├─ 全置換確認をキャンセル → SCR-006 解析結果
  ├─ 全置換成功 → SCR-001 一覧
  ├─ 全置換失敗 → SCR-006 エラー表示

  ├─ オンライン → オフライン → オフライン表示
  ├─ オフライン → オンライン → オフライン表示を解除し更新確認
  ├─ 新Service Worker検知 → 更新あり表示

  ├─ 更新あり → 更新 → 保存完了後にアプリを再読み込み
  ├─ 更新適用失敗 → エラー表示 → 再試行
  └─ 初回オフライン・アプリシェル未取得 → 起動不能表示

## 12. 実装メモ

- UIは見栄えよりも入力しやすさと生成結果確認を優先する
- 名簿入力は表形式を基本とする
- 表示テキストは日本語を基本とする
- ドメインロジックはUIコンポーネントに直書きしない
- 画面コンポーネントは、domain層の関数を呼び出すだけに近づける
- UIからIndexedDB、localStorageを直接操作せず、保存層を経由する
- IndexedDB初期化完了前に空状態を表示しない
- 全置換復元は解析、検証、確認、トランザクション実行を分離する
- 印刷用CSSは初期段階から用意する
- 正規Originは `https://draw-lab.bamboosato.com/` とし、ManifestとService Workerを同一Originから配信する
- Service Workerはアプリシェルと公開静的資産だけをCache Storageへ保存する
- IndexedDBの大会データ、入力途中の内容、JSON本文をService Workerのキャッシュへ保存しない
- React Routerの画面URLは、ホスティング側のSPAフォールバックで直接再読み込みできるようにする
- PWA状態テストは機能、非機能、データ、UI、正常系、異常系、境界値、状態遷移に分ける

## 13. SCR-L-001 リーグ一覧画面

リーグ一覧はトーナメント一覧とデータ領域を分離するが、一覧のページ構造、操作密度、表現、追加アクションメニューはトーナメント一覧に合わせる。

### 13.1 表示項目

| 項目 | 内容 |
|---|---|
| 大会名 | `League.title`。未設定の場合は「無題のリーグ」。会場を補助表示する |
| 種目 | `League.eventName`。その下に個人／ダブルス／チームを表示する |
| 開催日 | `League.date`。未設定の場合は `-` |
| 定員 | `League.capacity` |
| 状態 | 編集中／運用中／完了 |
| 最終更新 | `League.updatedAt` |
| アクション | 編集、リーグ表、その他の操作 |

一覧上部の概要帯には、全リーグ数、運用中数、完了数、編集中数を表示する。運用中は対戦カード確定済みかつ未完了、完了は`completed`、編集中はそれ以外とする。

初期表示は最終更新の新しい順とする。開催日と最終更新は見出しをクリックして昇順・降順を切り替えられるようにし、未設定・不正な日付は末尾へ表示する。同値の場合は切り替え前の相対順を維持する。

### 13.2 操作

| 操作 | 動作 |
|---|---|
| 新規作成 | 新規リーグを作成し、リーグ基本情報画面へ遷移する |
| 編集 | リーグ基本情報画面へ遷移する |
| リーグ表 | 対戦カード確定済みの場合だけリーグダッシュボードへ遷移する。未確定時は無効化し、理由をツールチップまたはARIAラベルで示す |
| 複製 | 基本情報・参加単位・選出・補欠・グループ・対戦設定を引き継いで新しいリーグIDおよび関連IDを発行する。対戦カードは未確定、結果・備考・順位は初期状態に戻す |
| 個別JSON出力 | 対象League一式をJSONとしてダウンロードする |
| 削除 | 確認ダイアログ後にリーグストアから削除する |
| 全リーグバックアップ | 保存済みの全Leagueを1つのバックアップJSONとしてダウンロードする |
| リーグ情報の復元 | リーグJSON復元画面へ遷移する |

一覧右上は`新規作成`ボタン、その右に横3点の追加アクションボタンを配置する。追加アクションには、バックアップグループの`全リーグバックアップ`と復元グループの`リーグ情報の復元`を配置する。各行の追加アクションには、リーグ情報グループの`複製`、`出力`、`削除`を配置する。

### 13.3 保存状態・空状態

トーナメント一覧と同じく、読込中、保存可能、保存中、保存エラーを区別する。読込中は空状態と誤認させない。リーグがない場合は、次の文言を表示する。

```text
保存済みのリーグはありません。
新規作成またはリーグ情報の復元から開始してください。
```

### 13.4 リーグJSON復元

リーグJSON復元画面は、個別リーグと全リーグバックアップを同じ画面で解析する。

- 個別リーグは、読込結果を確認後に`個別リーグを追加`で新規追加する。既存リーグは上書きしない。
- 全リーグバックアップは、バックアップ件数、現在の件数、出力日時を表示する。
- 全リーグの置換復元は、確認ダイアログの`全置換する`を経て実行する。
- 0件のバックアップも復元対象とし、現在の全リーグが削除されることを明示する。
- 解析・検証・保存に失敗した場合は、既存リーグを変更しない。

### 13.5 リーグ名簿入力・選出

リーグの名簿入力と選出者指定は同じ画面で行い、選出専用画面への遷移は設けない。

- 上部操作は左から`自動選出`、`行追加`、`空行削除`、`入力チェック`の順に配置する。
- `自動選出`は、入力済み参加者から定員分をランダムに選択し、現在のチェック状態を置き換える。入力済み参加者が定員未満の場合は全員を選択する。
- 名簿一覧の最左列に`選出`チェックボックスを配置する。チェックありを選出者、チェックなしを補欠として扱う。
- チェックなしの行全体（各セルと入力欄）は薄いグレーで表示する。補欠一覧や`繰り上げる`ボタンは設けず、チェックを付けることで選出者へ戻す。
- 表上部に`参加者数`、`選択済み`、`定員`を表示し、`選択済み`には現在チェックされている選出者数を表示する。選出者数が1名未満または定員を超える場合は`次へ`を無効にする。
- グループまたは対戦カードが存在する状態でチェック状態を変更した場合は、リセット確認後に再構成する。結果入力後はチェックボックスと自動選出を無効にする。
- 旧URL `/leagues/:id/edit/selection` は、互換性のため名簿入力・選出画面へリダイレクトする。
