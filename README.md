# draw-lab

Tournament draw maker with seed, bye, team, and region-aware placement.

シード、BYE、所属チーム、地区の偏りを考慮してトーナメント表を自動生成するWEBアプリのPoCです。

---

## 概要

`draw-lab` は、テニス大会・サークル大会などで使用するトーナメント表をWEBブラウザ上で作成するためのPoCアプリケーションです。

既存のExcel VBAトーナメント表作成アプリの仕様・操作思想を参考にしつつ、VBAコードやExcel固有の実装には依存せず、WEBアプリとして独自実装します。

主な対象は以下です。

- 参加者名簿からトーナメント表を自動生成する
- シングルス / ダブルスに対応する
- シード、BYE、所属チーム、地区の偏りを考慮する
- 生成したトーナメント表を画面で確認する
- ブラウザ印刷によりPDF保存する
- ローカル保存とJSONエクスポート / インポートに対応する

---

## PoCスコープ

最初のPoCでは、以下を実装対象とします。

- 新規トーナメント作成
- トーナメント基本情報入力
- 名簿入力
- Excel / スプレッドシートからのコピー＆ペースト入力
- CSV形式テキストの貼り付け
- 名簿バリデーション
- シード番号指定
- BYE自動補完
- 所属チームの偏りを考慮した配置
- 地区の偏りを考慮した配置
- 乱数シード保持
- SVG / HTMLによるトーナメント表プレビュー
- ローカル保存
- JSONエクスポート / インポート
- ブラウザ印刷によるPDF保存

詳細は [`docs/requirements.md`](docs/requirements.md) を参照してください。

---

## PoC対象外

最初のPoCでは、以下は対象外とします。

- ユーザー登録 / ログイン
- クラウド保存
- 共有URL発行
- 共同編集
- 試合結果入力
- スコア管理
- 勝ち上がり更新
- リーグ戦
- コンソレーション
- 3位決定戦
- 複数種目の一括管理
- Excelファイル直接読み込み
- Excelファイル出力
- 厳密な競技団体ルール完全準拠
- 既存VBAアプリとの完全互換

## 推奨技術構成

PoCでは、以下の構成を基本候補とします。

- React
- TypeScript
- Vite
- Vitest
- SVG / HTML renderer
- IndexedDB または localStorage

バックエンドは最初のPoCでは不要です。クラウド保存や共有URLは後続フェーズで検討します。

---

## 設計方針

実装では、以下の責務を分離します。

```text
UI
  ↓
入力バリデーション
  ↓
トーナメント生成ロジック
  ↓
トーナメント表データ
  ↓
SVG / HTMLレンダリング
  ↓
PDF出力・保存
```

特に、抽選ロジックと描画ロジックは分離します。

抽選ロジックは、可能な限り単体テスト可能な純粋関数として実装します。描画はSVG / HTMLを用い、Excelのセル結合や罫線表現には依存しません。

---

## 主要データモデル案

詳細は `docs/requirements.md` に記載しています。初期案として、以下のようなモデルを想定します。

- `Tournament`
- `Entrant`
- `DrawOptions`
- `GeneratedDraw`
- `DrawSlot`

生成結果は、乱数シードとともに保存し、同じ入力と同じ乱数シードで同じ結果を再現できることを目指します。

## 開発時の注意

- `docs/requirements.md` を要件の正とする
- PoC対象外の機能を安易に追加しない
- 既存VBAコードを移植しない
- 仕様・操作思想は参考にするが、WEBアプリとして独自実装する
- 抽選ロジックと描画ロジックを分離する
- 乱数シードによる再現性を維持する
- 生成ロジックには単体テストを追加する
