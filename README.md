# draw-lab

参加者名簿からトーナメント表・リーグ表を作成し、結果入力、ローカル保存、JSONバックアップ、印刷までをブラウザ内で行うWEBアプリです。

本番URL: [draw-lab.bamboosato.com](https://draw-lab.bamboosato.com/)

初回正式リリースは **1.0.0**（2026-08-21）です。以下はその後の追加実装を含む、現在のmainの機能です。実装と文書の対応は [実装状況](docs/implementation-status.md)、変更履歴は [CHANGELOG.md](CHANGELOG.md) を参照してください。

## トーナメント

- シングルス / ダブルス / チームの基本情報・名簿入力
- Excel・スプレッドシートからのコピー＆ペースト、CSV形式テキストの貼り付け
- 名簿のエラー・警告バリデーション
- 4 / 8 / 16 / 32 / 64 / 128ドロー、シード番号指定、BYE自動補完
- 所属チーム・地区の偏りを考慮した配置、シード配置方式・選手配置順序の設定
- 乱数シードを保持した再現可能なドロー生成と、初回生成後の入力変更に応じた自動再生成
- 対戦カードの確定、勝敗・セットごとのゲーム数・備考入力、Walk Over（不戦勝）の記録
- 1 / 3 / 5セットマッチ、未実施カードでスコアから勝者が明確な場合の自動選択、勝ち上がり・スコアの表への反映
- トーナメントの完了と、確認後の編集再開
- SVGプレビュー、片山 / 両山、ドロー番号・シード番号位置、線の太さ・文字配置などの出力形式設定
- 両山表示のページ分割、ブラウザ印刷によるPDF保存（A4縦）
- 画面の表示倍率100〜300%、ピンチ・ドラッグ（印刷倍率には反映しない）

## リーグ

- 個人 / ダブルス / チームの基本情報・名簿入力
- 全員 / ランダム / 手動の選出、補欠の管理、対戦カード確定前の参加者入替
- グループ分け、総当たりの候補カード生成、カード単位の有効 / 無効選択と確定
- 勝 / 分 / 負、セットごとのゲーム数、備考、Walk Overの入力
- 勝点、同点時の直接対決、獲得セット率、獲得ゲーム率、グループ内順による自動順位と訂正順位の確定
- グループ別リーグ表、詳細表示の切替、入力済み結果付き / 手書き用のPDF・印刷
- リーグの完了と編集再開、個別JSON・全リーグバックアップ

## リーグからトーナメントを作成

トーナメント一覧の追加アクションメニューにある「リーグから作成」で、対戦カード確定済みのリーグと順位区分（例: 1-2位）を選択します。大会情報・参加者情報・グループ内順位を引き継ぎ、グループと順位を考慮した配置でトーナメントを生成できます。

1トーナメントにつき1順位区分を扱うスナップショット連携です。作成後のリーグ変更をトーナメントへ自動同期する機能や、両者の結果を相互反映する機能はありません。

## 共通機能・利用環境

- ホーム画面でトーナメント・リーグの件数、状態、最近更新した項目を確認
- 一覧の並び替え、複製、削除、個別JSON出力・ファイルからの復元
- IndexedDBによる自動保存、旧トーナメントデータのlocalStorageからの移行
- モバイルヘッダーとメニュー、対応環境での画面遷移アニメーション
- PWAのインストール案内、オフライン起動、更新案内とユーザー操作による更新

主な利用対象はPCのChrome / Edgeです。スマートフォンでは閲覧・簡易確認とメニュー操作に対応しています。PWA・オフライン利用には対応ブラウザと、オンラインでの初回読み込み・キャッシュ準備が必要です。PDFのページ数や余白はブラウザの印刷設定によって変わります。

## 保存・バックアップ

大会情報は利用中のブラウザのIndexedDBへ保存します。アプリから自動的にクラウドへアップロードされません。保存データはURLのOriginごとに分かれ、別PC・別ブラウザ・別OriginへはJSONで移します。

| ファイル | 対象 | 復元時の動作 |
|---|---|---|
| 個別大会JSON | トーナメント1件と、その連携情報 | 新しいIDで追加 |
| 全大会バックアップ | 全トーナメントと、その連携情報 | 確認後、トーナメントと連携情報を全置換 |
| 個別リーグJSON | リーグ1件 | 新しいIDで追加 |
| 全リーグバックアップ | 全リーグ | 確認後、リーグを全置換 |

「全大会バックアップ」にはリーグ本体を含みません。アプリ全体を移す場合は、トーナメントとリーグの両方をバックアップしてください。トーナメント側の復元はリーグを変更せず、リーグ側の復元はトーナメントを変更しません。

JSONやPDFには参加者名・所属・地区などの情報が含まれる場合があります。ブラウザの保存領域を削除するとローカルデータを失うため、必要なデータはJSONで保管してください。

## 現在の対象外

ユーザー登録・ログイン、クラウド保存、共有URL、共同編集、コンソレーション、3位決定戦、複数種目の一括管理、Excelファイルの直接入出力、サーバーサイドPDF生成は対象外です。競技団体の厳密なルール完全準拠や既存VBAアプリとの完全互換も保証しません。

## 開発

```bash
npm install
npm run dev
```

検証コマンド:

```bash
npm run test:security
npm run audit:security
npm test
npm run typecheck
npm run build
```

React / TypeScript / Vite / React Router / Vitestを使用します。生成・集計処理はReactから独立した`src/domain/`、画面は`src/pages/`と`src/components/`、保存は`src/storage/`、状態管理とJSON変換の一部は`src/app/`に分離しています。既存VBAコードやExcel固有の実装は移植しません。

## CIと依存性の監査

GitHub ActionsはPull Requestと`main`へのpushで、Node.js 24と`npm ci`を使って検証します。監査ルールのテスト、本番依存の`npm audit --omit=dev --json`、開発依存を含む`npm audit --include=dev --json`、型チェック、単体テスト、本番ビルドを順に実行します。

重大度を問わず、未承認の脆弱性や監査の通信・解析失敗があればCIは失敗します。現在の一時例外は0件です。例外を認める場合も、開発依存だけを対象に、アドバイザリ・バージョン・依存パス・有効期限を限定し、本番依存とCriticalは除外できません。監査JSONは成功・失敗にかかわらず`dependency-audit` artifactへ保存します。詳細は[依存性セキュリティ監査](docs/dependency-security.md)を参照してください。
